## v0.3 — 多分镜节奏自动分配器

### 输入 Input

- N 个分镜（N ≥ 2）
- 每个分镜的"权重"（如 `[1/5, 1/5, 1/5, 1/5, 1/5]`）或"重要性"（1-5 分）
- 总时长（秒），如 30s

### 输出 Output

- 每个分镜的 `{start_time, end_time, duration_seconds, weight}` 列表
- JSON 格式，便于程序消费
- Markdown 表格，便于人读

### 验收标准 Acceptance

- **精度**：与 Mx-Shell 在视频中示范的人工分配对比，相对误差 < 10%
  - 测试集：视频中提到的 5 分镜战斗戏（opening / 引爆 / 主击 / 收尾 / 落幕）
  - 误差计算：`sum(abs(algorithmic_i - human_i)) / total_duration`
- **边界**：N=1 时应输出 `[{start: 0, end: total, ...}]`
- **最小分镜时长**：单分镜时长 < 1.5s 应报警（AI 视频模型通常无法生成 < 1.5s 的有效镜头）
- **算法可解释**：能从输出反推权重如何归一化

### 风险 Risks

- **权重悬殊**：分镜权重 95% vs 5% 时，算法可能给 5% 那个 0.5s（< 1.5s 阈值）
  - **缓解**：最小分镜时长阈值 + 把剩余时长全给最后一个
- **总时长不是分镜时长的整数倍**：如 5 分镜 + 30s = 每个 6s，但分镜类型不同（快切 vs 慢镜头）应有不同基准
  - **缓解**：v0.3 仅做"按权重均匀分配"，复杂调度推迟到 v0.3.1

### 优先级

高。CHANGELOG `Planned` 段已声明。

## v0.4 — LLM-as-judge 提示词质量评分

### 输入 Input

- `prompt.md`（v0.2 三大段格式的提示词）
- 可选：参考评分样本（用于校准）

### 输出 Output

- 0-100 分（整数）
- 5 条改进建议（按"高/中/低"优先级排序）
- 维度细分（每维度 0-20 分）：
  - 三大段齐全度
  - 顺序正确性
  - 去 AI 味关键词覆盖
  - 景别/构图/运镜齐备
  - 故事内容三段式

### 验收标准 Acceptance

- **与人工评分的相关性**：ρ（Spearman）> 0.7
  - 测试集：50 份提示词，每份由 3 位 Mx-Shell 风格的人类评分员打分取中位数
- **建议可执行**：每条建议必须能在 ≤ 2 步操作内落地
- **跨模型一致性**：用 Claude / GPT-4 / Gemini 各跑一遍，ρ 内部互评 > 0.6

### 风险 Risks

- **礼貌高分**：LLM 倾向给 80-90 分（"好话说尽"），需 few-shot 示例校准
  - **缓解**：在 `references/quality-rubric.md`（v0.4 新增）放 10 份 0-100 分的"锚点样本"
- **幻觉建议**：LLM 可能建议"加参考图"而原提示词已含
  - **缓解**：建议必须引用原文（如"在第 3 行已有【基础设定】，但缺声音限制"）
- **成本**：每次评分调一次 LLM，50 份测试集 × 3 模型 = 150 次调用
  - **缓解**：批处理 + 缓存；v0.4 默认用本地 LLM（如 Ollama）

### 优先级

中。是 v1.0 平台对接的"质量门槛"前置。

## v1.0 — 平台 API 对接（即梦 / Vidu / 可灵 / 小云雀 / Sora / Runway）

### 输入 Input

- `prompt.md`（v0.2 三大段格式）
- 模型选择：`["jimeng", "vidu", "kling", "xiaoyunque", "sora", "runway"]`（v1.0 支持的 6 个平台）
- 可选：参考图 URL、时长、宽高比

### 输出 Output

- 生成视频 URL（公开可访问）
- 任务 ID（用于查询进度）
- 平台侧元数据（model_version、seed、cost 等）
- 失败时的错误码 + 重试建议

### 验收标准 Acceptance

- **成功调用**：6 个平台中至少 1 个端到端跑通（成功生成视频 + 拿到 URL）
- **错误处理**：401 / 429 / 5xx 全部有对应重试 / 提示
- **接口一致**：6 个平台在调用层是同一组 CLI：`video_gen.py --platform kling --prompt prompt.md`
- **可观测**：每次调用都打印 [START] / [POLL] / [SUCCESS] / [FAIL] 状态
- **成本控制**：默认不烧钱（先 dry-run，仅前 3 个平台真发请求）

### 风险 Risks

- **API 变化频繁**：即梦 / Vidu 等国内平台 3-6 月一次大版本
  - **缓解**：版本锁定 + 月度回归测试 + 抽象 adapter 层
- **账号 / 付费墙**：sora / runway 需要付费 API key
  - **缓解**：v1.0 默认不调用付费平台，仅 dry-run 演示接口
- **内容审核**：国内平台对"原子朋克 / 战斗"等可能有审核
  - **缓解**：在 prompt 中预置审核友好短语，失败时自动改写

### 优先级

低（v0.3 / v0.4 完成后再启动）。

## 启动顺序

1. **v0.3 优先**：多分镜节奏分配是用户最常手写、最容易出错的环节
2. **v0.4 跟进**：评分系统可作为 v1.0 平台对接的"质量门槛"
3. **v1.0 收官**：依赖 v0.4 的评分结果做平台选择

- 英文版 SKILL.md 全文翻译
- 10 / 15 套风格预设的英文翻译
